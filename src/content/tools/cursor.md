# Cursor란?

Cursor는 AI 기능을 중심에 두고 설계된 코드 에디터입니다.

VS Code에 익숙한 개발자가 자연스럽게 사용할 수 있는 편집 환경 위에, 코드베이스를 이해하는 채팅, 자동완성, 인라인 수정, 멀티 파일 변경, 에이전트 작업 흐름을 결합했습니다.

일반적인 IDE가 코드 작성 공간에 AI 기능을 추가한 형태라면, Cursor는 처음부터 "AI와 함께 개발하는 방식"을 중심으로 제품 경험을 재구성한 도구에 가깝습니다.

---

# Cursor의 핵심 특징

Cursor의 가장 큰 특징은 AI가 에디터 안에서 현재 코드 맥락을 바로 읽고 수정할 수 있다는 점입니다.

개발자는 별도의 챗봇에 코드를 복사해 붙여넣지 않고, 현재 열려 있는 파일과 프로젝트 구조를 기반으로 질문하고 변경을 요청할 수 있습니다.

## 코드베이스 이해

Cursor는 프로젝트 파일과 선택한 코드, 참조한 문서, 관련 컨텍스트를 바탕으로 답변하거나 코드를 수정합니다.

단순히 일반적인 예제 코드를 생성하는 것이 아니라, 현재 저장소의 구조와 기존 구현 방식을 참고해 작업할 수 있습니다.

### 활용 예시

- 낯선 코드베이스 구조 파악
- 특정 함수나 컴포넌트의 역할 설명
- 여러 파일에 걸친 버그 수정
- 기존 스타일에 맞춘 새 기능 구현
- 타입 오류와 린트 오류 해결
- 라이브러리 문서를 참고한 코드 작성

---

## Agent 모드

Cursor의 Agent 모드는 자연어로 요청한 작업을 여러 단계에 걸쳐 처리하는 기능입니다.

사용자가 "이 API 응답에 맞게 프론트엔드 상태 처리를 수정해줘"처럼 요청하면, 관련 파일을 찾고, 코드를 수정하고, 필요한 경우 명령을 실행하면서 작업을 이어갈 수 있습니다.

작업 범위가 명확할수록 결과가 좋아집니다. 작은 기능 구현, 버그 수정, 테스트 보강처럼 완료 조건이 분명한 작업에 특히 잘 맞습니다.

---

## Tab 자동완성

Cursor Tab은 단순한 한 줄 자동완성보다 더 넓은 맥락을 보고 다음 수정을 제안하는 기능입니다.

방금 작성한 코드, 주변 파일, 반복되는 패턴을 바탕으로 여러 줄 수정이나 다음 작업을 예측해 제안할 수 있습니다.

반복적인 컴포넌트 작성, 타입 추가, 비슷한 로직 확장처럼 패턴이 분명한 작업에서 생산성이 크게 올라갑니다.

---

## 인라인 수정

Cursor는 선택한 코드 블록을 대상으로 바로 수정 요청을 할 수 있습니다.

예를 들어 "이 함수를 더 읽기 쉽게 바꿔줘", "에러 처리를 추가해줘", "이 컴포넌트를 Tailwind 스타일로 정리해줘"처럼 특정 범위만 빠르게 고칠 수 있습니다.

전체 파일을 크게 바꾸기보다 작은 단위로 의도를 전달할 수 있어, 기존 코드의 흐름을 유지하면서 수정하기 좋습니다.

---

# 주요 기능

## AI Chat

프로젝트에 대해 질문하고, 특정 파일을 참조하고, 코드 흐름을 설명받을 수 있습니다.

새로운 코드베이스에 들어갔을 때 "이 폴더 구조가 어떻게 되어 있는지", "이 페이지는 어떤 데이터 흐름으로 동작하는지"를 빠르게 파악하는 데 유용합니다.

---

## Multi-file editing

Cursor는 여러 파일에 걸친 변경을 한 번의 작업으로 처리할 수 있습니다.

컴포넌트 이름 변경, API 타입 수정, 라우팅 구조 변경, 공통 유틸 분리처럼 여러 파일이 함께 바뀌어야 하는 작업에 적합합니다.

---

## Docs 참조

Cursor는 라이브러리나 프레임워크 문서를 컨텍스트로 참조할 수 있습니다.

React, Next.js, Tailwind, Supabase 같은 도구를 사용할 때 문서 기반으로 더 정확한 코드를 작성하도록 도울 수 있습니다.

---

## 터미널과 개발 흐름

Cursor는 에디터 안의 터미널, Git, 빌드 명령, 테스트 명령과 함께 사용하기 좋습니다.

AI가 수정한 결과를 바로 실행하고 확인하면서 개발자가 최종 판단을 내리는 흐름에 잘 맞습니다.

---

# Cursor의 장점

## 1. VS Code 사용자에게 익숙하다

Cursor는 VS Code 계열의 사용 경험을 기반으로 하기 때문에 기존 단축키, 확장, 에디터 습관을 유지하기 쉽습니다.

AI 기능을 쓰기 위해 완전히 새로운 개발 환경을 배울 필요가 적습니다.

---

## 2. 코드 작성 속도가 빠르다

Tab 자동완성, 인라인 수정, Agent 모드가 한 에디터 안에 들어 있어 작은 수정부터 큰 작업까지 빠르게 이어갈 수 있습니다.

특히 반복 패턴이 많은 프론트엔드 컴포넌트, API 타입 정리, 테스트 보강에서 효율이 좋습니다.

---

## 3. 질문과 수정이 같은 공간에서 이루어진다

코드를 읽다가 궁금한 점을 바로 묻고, 답변을 바탕으로 곧바로 수정까지 이어갈 수 있습니다.

별도의 AI 채팅 도구와 에디터 사이를 계속 오가지 않아도 된다는 점이 큰 장점입니다.

---

# 주의할 점

Cursor가 코드베이스를 이해하더라도 최종 리뷰는 개발자가 해야 합니다.

AI가 제안한 변경은 프로젝트의 숨은 요구사항, 보안 정책, 성능 제약, 팀 컨벤션을 완벽히 알지 못할 수 있습니다.

또한 너무 큰 작업을 한 번에 맡기면 수정 범위가 넓어지고 리뷰가 어려워질 수 있으므로, 기능 단위나 파일 단위로 나누어 요청하는 것이 좋습니다.

### 좋은 요청 방식

- "이 컴포넌트 안에서만 상태 처리 로직을 정리해줘"
- "현재 API 타입에 맞게 이 페이지의 타입 오류를 고쳐줘"
- "기존 UI 스타일을 유지하면서 empty state를 추가해줘"
- "수정 후 어떤 파일이 바뀌었는지 요약해줘"

---

# Cursor는 어떤 사람에게 적합할까?

- VS Code 기반 개발 환경을 선호하는 개발자
- AI 자동완성과 에이전트 기능을 한 에디터에서 쓰고 싶은 사용자
- 프론트엔드와 풀스택 작업을 빠르게 반복하는 팀
- 낯선 코드베이스를 자주 읽고 수정해야 하는 개발자
- 작은 기능 구현과 리팩터링을 자주 처리하는 프로젝트
- 개발 중 질문, 수정, 검증을 한 흐름으로 이어가고 싶은 사용자

---

# 마무리

Cursor는 AI를 에디터의 보조 기능이 아니라 개발 경험의 중심에 둔 코드 에디터입니다.

코드베이스를 읽고, 질문에 답하고, 여러 파일을 수정하고, 반복 작업을 빠르게 처리하는 데 강점이 있습니다. VS Code에 익숙한 개발자가 AI 기반 개발 흐름을 본격적으로 도입할 때 가장 접근하기 쉬운 선택지 중 하나입니다.
