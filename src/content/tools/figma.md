# Figma란?

Figma는 브라우저 기반의 협업 UI 디자인 플랫폼입니다.

인터페이스 디자인, 프로토타이핑, 디자인 시스템 관리, 개발자 핸드오프를 한 공간에서 처리할 수 있어 제품 디자인 팀의 표준 도구처럼 사용됩니다.

Figma의 핵심은 "디자인 파일을 팀 전체가 함께 다루는 것"입니다. 디자이너, 기획자, 개발자, PM이 같은 파일을 보면서 화면을 만들고, 코멘트를 남기고, 컴포넌트를 정리하고, 구현에 필요한 정보를 확인할 수 있습니다.

---

# Figma의 핵심 특징

Figma는 정적인 디자인 툴이 아니라 협업 중심의 제품 디자인 워크스페이스입니다.

UI 설계부터 프로토타입, 디자인 시스템, 개발 전달까지 제품 제작 흐름 전반에 관여합니다.

## 실시간 협업

Figma는 여러 사람이 같은 파일을 동시에 편집하고 확인할 수 있습니다.

디자인 리뷰, 코멘트, 버전 관리, 팀 라이브러리 공유가 자연스럽게 연결되어 있어 원격 팀이나 크로스펑셔널 팀에 특히 잘 맞습니다.

### 활용 예시

- 웹사이트와 앱 UI 디자인
- 사용자 플로우와 와이어프레임 제작
- 클릭 가능한 프로토타입 구성
- 디자인 시스템과 컴포넌트 관리
- 개발자에게 스펙과 에셋 전달
- 제품 리뷰와 피드백 수집

---

## 프로토타이핑

Figma는 화면 간 이동, 오버레이, 인터랙션, 애니메이션을 설정해 실제 제품에 가까운 프로토타입을 만들 수 있습니다.

개발 전에 사용자 흐름을 검토하거나, 팀 내부 리뷰와 사용자 테스트를 진행할 때 유용합니다.

---

## 디자인 시스템

Figma는 컴포넌트, 변수, 스타일, 팀 라이브러리를 통해 디자인 시스템을 관리할 수 있습니다.

버튼, 입력 필드, 컬러, 타이포그래피, 간격 같은 반복 요소를 시스템화하면 여러 제품 화면에서 일관성을 유지하기 쉽습니다.

---

## Dev Mode

Figma의 Dev Mode는 개발자가 디자인 파일을 구현 관점에서 확인할 수 있도록 돕는 기능입니다.

개발자는 디자인 파일을 수정하지 않고도 간격, 색상, 에셋, CSS 정보, 컴포넌트 상태, 구현 준비 여부를 확인할 수 있습니다.

---

# 주요 기능

## UI 디자인

프레임, 오토레이아웃, 컴포넌트, 스타일을 사용해 웹과 모바일 UI를 정교하게 만들 수 있습니다.

복잡한 디자인 툴에 익숙한 전문가뿐 아니라 제품 팀 전체가 접근하기 쉬운 인터페이스를 제공합니다.

---

## FigJam과 아이데이션

Figma 생태계에는 FigJam 같은 화이트보드 도구도 포함됩니다.

아이디어 정리, 워크숍, 사용자 여정 맵, 회고, 팀 브레인스토밍을 디자인 파일과 가까운 환경에서 진행할 수 있습니다.

---

## 플러그인과 확장성

Figma는 플러그인 생태계가 크기 때문에 아이콘, 콘텐츠 생성, 접근성 검사, 디자인 토큰, 코드 연결 같은 작업을 확장할 수 있습니다.

팀의 워크플로우에 맞게 디자인 작업을 자동화하기 좋습니다.

---

## AI 기반 작업

Figma는 최근 AI 기능을 통해 아이디어 생성, 프로토타입 제작, 디자인 보조, 콘텐츠 생성 같은 작업을 강화하고 있습니다.

다만 AI 결과물은 디자인 시스템, 브랜드 톤, 실제 제품 요구사항에 맞게 사람이 다시 정리해야 합니다.

---

# Figma의 장점

## 1. 협업이 강하다

파일 공유, 실시간 편집, 댓글, 팀 라이브러리, Dev Mode가 하나의 흐름으로 이어집니다.

그래서 디자인 결과물을 따로 전달하기보다 팀이 같은 기준을 보며 논의할 수 있습니다.

---

## 2. 디자인 시스템 관리에 적합하다

컴포넌트와 변수 기반으로 UI 패턴을 관리할 수 있어, 제품 규모가 커질수록 효과가 커집니다.

여러 팀이 같은 디자인 언어를 유지해야 하는 조직에 특히 적합합니다.

---

## 3. 개발 전달이 쉽다

Dev Mode를 사용하면 개발자는 디자인 파일에서 구현에 필요한 정보를 직접 확인할 수 있습니다.

디자이너와 개발자 사이의 반복적인 질문을 줄이고, 디자인 의도를 구현으로 옮기는 과정을 더 명확하게 만듭니다.

---

# 주의할 점

Figma는 강력하지만 파일과 시스템이 커질수록 관리 규칙이 중요합니다.

컴포넌트 네이밍, 변수 구조, 라이브러리 관리, 권한 설정을 정리하지 않으면 파일이 빠르게 복잡해질 수 있습니다.

또한 Figma에서 만든 디자인이 곧바로 좋은 제품 구현을 보장하지는 않습니다. 실제 코드, 반응형 조건, 접근성, 성능, 데이터 상태는 개발 과정에서 별도로 검증해야 합니다.

---

# Figma는 어떤 사람에게 적합할까?

- UI/UX 디자이너
- 제품 디자인 팀
- 디자인 시스템을 관리하는 조직
- 개발자와 긴밀히 협업하는 팀
- 프로토타입과 사용자 흐름을 빠르게 검토해야 하는 팀
- 웹과 모바일 제품을 지속적으로 개선하는 스타트업과 기업

---

# 마무리

Figma는 단순한 UI 디자인 툴이 아니라 제품 팀 전체가 디자인을 함께 만들고 구현으로 연결하는 협업 플랫폼입니다.

디자인 시스템, 프로토타이핑, Dev Mode를 잘 활용하면 제품 제작 과정에서 디자인과 개발 사이의 간격을 크게 줄일 수 있습니다.
